# Проблемы и риски

- За период между запросами может скапливаться достаточно много обновлений информации, отсутствие которой в остальной системе делает ее непоной и неэффективной.
- В случае сбоя при вызове сервиса ins-product-aggregator или API страховых компаний указанный большой объем информации не попадает в систему как минимум еще в течение интервала времени между запросами.
- Большое количество информации, передаваемое в систему за один запрос само по себе может стать причиной отказа (например падения запроса по таймауту).

# Вывод и предложения по решению

- Следует внеднить получение информации системой от страховых компаний согласно паттерну EDA
- Сервис ins-product-aggregator, зависящий от API страховых компаний, должен посылать запросы к ним с большей частотой, и полученные результаты отправлять в core-api и ins-comp-settlement через очереди.
