# osago-aggregator. Детали реализации.

1. Требуется ли ему своё хранилище данных?
   - Нет необходимости, так как сервис osago-aggregator выступает как фасад для API внешних систем. 
2. Какой API он предоставляет core-app? Определите средство интеграции между сервисами core-app и osago-aggregator.
   - REST API для получения запроса из core-app
   - Очередь для отправки предложений в core-app
3. API для веб-приложения в core-app.
   - core-app реализует REST API для веб-приложения. Веб-приложение использует микро-фреймворки настроенные на регулярное опрашивание API core-app.
4. Применение паттернов отказоустойчивости:
   - Rate Limiting. В контексте osago-aggregator не применяем, так как нет необходимости защищать этот модуль непосредственно от большого количества запросов. Эту защиту можно применить на уровне core-app при взаимодействии с пользовательским web порталом.
   - Circuit Breaker. Применяем в osago-aggregator для вызовов REST API внешних систем (страховых компаний).
   - Retry. Применяем в osago-aggregator для вызовов REST API внешних систем (страховых компаний).
   - Timeout. Применяем в osago-aggregator для вызовов REST API внешних систем (страховых компаний).
